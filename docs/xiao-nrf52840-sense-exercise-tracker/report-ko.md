# Seeed Studio XIAO nRF52840 Sense 기반 손목 착용형 운동 인식

**기술 타당성 및 개발 보고서**<br>
**작성일:** 2026년 9월 5일<br>
**상태:** 제안 아키텍처 및 검증 계획

## 요약

Seeed Studio XIAO nRF52840 Sense는 손목 착용형 운동 추적기의 첫 프로토타입에 적합하다. 6축 관성 측정 장치(IMU), Bluetooth Low Energy 통신, 작은 크기, Cortex-M4F 프로세서를 이용해 움직임 기록, 세트 구간 탐지, 반복 횟수 계산, 제한된 운동 목록의 분류를 구현할 수 있다.

의도한 사용자 경험은 범위를 명확히 정하면 구현 가능하다.

1. 사용자가 헬스장에 들어가 운동 세션을 직접 시작하거나 신뢰할 수 있는 동작 감지 알림을 확인한다.
2. 사용자는 매번 운동을 선택하지 않고 지원되는 운동을 자유롭게 수행한다.
3. 밴드는 손목 움직임을 기록하여 휴대폰으로 전송하거나 짧은 구간을 로컬에 보관한다.
4. 처리 파이프라인이 운동 구간, 운동 종류, 세트, 반복 횟수를 판별한다.
5. 앱은 운동 요약을 보여주고 사용자가 오류를 수정할 수 있게 한다.

이 보드는 들어 올린 중량, 가한 힘, 심박수, 근육 활성도, 근육 산소량, 근육 성장량을 직접 측정할 수 없다. “근육 사용량”은 인식된 운동과 사용자가 입력한 중량을 바탕으로 계산한 **훈련 자극 추정 점수**로만 제공해야 한다. “근육 성장량”을 이 센서가 측정한 값처럼 표현해서는 안 된다.

권장 MVP는 손목 움직임으로 구분하기 쉬운 운동 5~8개를 지원하고, 주된 추론은 휴대폰에서 수행하며, 보드는 정확한 타임스탬프가 포함된 IMU 데이터 수집과 BLE 전송을 담당한다. 엣지 추론은 휴대폰 모델이 사용자 독립 검증을 통과한 후 도입하는 것이 좋다.

## 1. 제품 목표

### 1.1 목표 사용자 흐름

```text
헬스장 입장
  -> 운동 세션 시작 또는 시작 확인
  -> 원하는 운동 수행
  -> 헬스장 퇴장 / 세션 종료
  -> 운동 종류, 세트, 반복 횟수 확인
  -> 잘못된 결과 수정
  -> 근육군별 자극과 장기 추세 확인
```

수정 기능은 단순한 오류 처리 수단이 아니라 제품의 핵심 기능이다. 사용자의 동의를 전제로 수정된 기록을 개인화 모델과 전체 모델 개선을 위한 고품질 피드백 라벨로 사용할 수 있다.

### 1.2 측정 범위

| 출력 | 구분 | 의미 |
|---|---|---|
| 선형 가속도 | 직접 측정 | 중력과 움직임을 포함한 3축 IMU 신호 |
| 각속도 | 직접 측정 | 3축 자이로스코프 신호 |
| 운동 종류 | 모델 추론 | 명시적으로 지원하는 클래스 중 확률 예측 |
| 세트 경계 | 모델 추론 | 움직임과 휴식 패턴에서 구한 시작·종료 시점 |
| 반복 횟수 | 모델 추론 | 반복되는 동작 주기에서 구한 횟수 |
| 템포 / 가동 범위 일관성 | 모델 추론 | 상대적 움직임 특성이며 해부학적 관절 각도가 아님 |
| 들어 올린 중량 | 밴드에서 알 수 없음 | 사용자 입력 또는 운동 기구 연동 필요 |
| 근육군별 자극 | 파생 추정치 | 운동 매핑, 세트, 횟수, 중량, 템포, 노력도 조합 |
| 근육 활성도 | 측정하지 않음 | EMG 등 근육 전용 센서 필요 |
| 근육 성장량 | 측정하지 않음 | 장기 신체 측정과 더 넓은 맥락 필요 |

## 2. 하드웨어 평가

### 2.1 보드와 프로세서

XIAO nRF52840 Sense의 크기는 21 × 17.8 mm이며 온보드 안테나, USB Type-C, 배터리 충전 회로, PDM 마이크, LSM6DS3TR-C 6축 IMU가 포함된다. nRF52840은 부동소수점 연산을 지원하는 64 MHz Arm Cortex-M4 프로세서, 1 MB 내부 플래시, 256 KB RAM을 제공한다. 데이터 수집, 필터링, 특징 추출, BLE 통신, 작은 양자화 모델을 처리할 수 있지만 Bluetooth 스택과 런타임을 포함해 RAM을 계산해야 한다.

Seeed의 현재 위키에는 2 MB 온보드 플래시가 추가로 표기되어 있다. 그러나 현재 연결된 Sense 회로도에서 외부 플래시 위치는 `DNP`(미실장)로 표시된다. 따라서 실제 보드 리비전과 BOM을 확인하기 전까지 외부 플래시를 확정 자원으로 취급해서는 안 된다. 이 확인 없이 전체 세션 저장 기능이 외부 플래시에 의존해서는 안 된다.

현재 Seeed 비교표와 이전 보드 문서의 Bluetooth 버전 표현에도 차이가 있다. 제품 요구사항은 마케팅 페이지의 가장 높은 버전 숫자가 아니라 실제 선택한 펌웨어 스택에서 활성화하고 검증한 BLE 기능을 기준으로 정해야 한다.

### 2.2 IMU

온보드 STMicroelectronics LSM6DS3TR-C는 다음을 제공한다.

- 3축 가속도와 3축 각속도
- ±2, ±4, ±8, ±16 g 가속도 범위
- ±125, ±250, ±500, ±1000, ±2000 dps 자이로스코프 범위
- 16비트 출력, I2C/SPI, 인터럽트, 내장 모션 기능
- 4 KB 스마트 FIFO
- 데이터시트 조건에서 가속도·자이로 고성능 모드 약 0.90 mA, 208 Hz 일반 모드 0.45 mA, 52 Hz 저전력 결합 모드 0.29 mA

100 Hz에서 가속도와 자이로스코프 원시 데이터는 타임스탬프와 프레이밍을 제외하고 샘플당 12바이트가 필요하다. 따라서 4 KB FIFO에는 약 341개 샘플, 즉 약 3.4초만 저장된다. 인터럽트 기반 배치 처리에는 유용하지만 운동 전체를 저장할 수는 없다.

### 2.3 권장 데이터 수집 설정

모델 개발용 첫 기록은 다음 설정으로 시작한다.

| 설정 | 초기값 | 이유 |
|---|---:|---|
| 샘플링 주파수 | 100 Hz | 빠른 전환을 보존하면서 고품질 기준 데이터 수집 |
| 가속도 범위 | ±8 g | 헬스장 동작에 적절한 시작 여유이며 클리핑 검증 필요 |
| 자이로 범위 | ±1000 dps | 빠른 동작의 클리핑 여부 검증 필요 |
| 신호 | 가속도 + 자이로 | 자세가 다른 유사 운동 구분에 두 모달리티가 유리 |
| 타임스탬프 | 단조 증가 장치 시간 | 손실과 지터 검출에 필요 |
| 패킷 순번 | 증가하는 카운터 | BLE 패킷 손실 정량화에 필요 |

검증 후 100 Hz와 50 Hz를 비교한다. 2024년의 한 운동 분류 연구에서는 해당 데이터셋을 20 Hz까지 다운샘플링해도 전체 성능 감소가 작았지만, 이 결과를 이 보드·착용 위치·운동 목록에 그대로 적용할 수는 없다. 제품 샘플링 주파수는 자체 정확도와 배터리 측정 결과로 결정해야 한다.

### 2.4 전원과 배터리

보드에는 TI BQ25101 단일 셀 리튬이온/리튬폴리머 충전기가 사용된다. Seeed는 보드 수준에서 50 mA 또는 100 mA 충전 전류를 선택할 수 있다고 설명한다. 배터리 용량, 케이스, 스트랩, 방수, 조립 후 무게는 개발 보드가 제공하는 사양이 아니라 별도의 제품 설계 항목이다.

Seeed 문서에서 `P0.14`는 `READ_BAT_ENABLE`, `P0.31`은 `AIN7_BAT`이다. 배터리 ADC를 읽기 전 `P0.14`를 LOW로 설정해야 하며, 충전 중에는 위험한 HIGH 상태를 사용하지 말라는 주의사항이 있다.

배터리 수명은 완성된 프로토타입에서 측정해야 한다. MCU 또는 IMU의 개별 데이터시트 전류만으로 전체 기기의 사용 시간을 계산하면 안 된다. 데이터 수집, BLE 전송, 연결 해제 상태 기록, 대기, 세션 감지, 충전을 각각 시험해야 한다. 모션 인터럽트나 휴대폰 명령으로 전체 속도 처리를 깨우는 것이 좋으며, 온종일 최대 속도로 IMU와 BLE를 계속 동작하는 설계는 권장하지 않는다.

### 2.5 마이크 권장사항

온보드 마이크는 첫 운동 인식 MVP에 필요하지 않다. 헬스장 음성은 개인정보 위험과 불규칙한 배경 소음을 추가하지만 반복 횟수 계산에 확실한 가치를 제공하지 않는다. 이후 별도 동의를 받은 실험에서 명확한 이점이 입증되기 전까지 비활성화한다.

## 3. 시스템 아키텍처

```text
XIAO 밴드
  IMU 샘플링 -> 타임스탬프 -> FIFO 읽기 -> 패킷 순번 -> BLE
       |                                                    |
       +-> 선택적 모션 게이트 / 엣지 반복 후보 검출         v
                                                      모바일 앱
                           세션 분할 -> 운동 분류
                           -> 세트/횟수 계산 -> 수정 UI
                                      |
                                      v
                           로컬 요약 / 선택적 클라우드
                           명시적 동의 기반 모델 학습
```

### 3.1 장치의 역할

- IMU 초기화 및 보정
- 동기화된 가속도·자이로스코프 샘플 수집
- 단조 증가 타임스탬프와 패킷 순번 추가
- FIFO 배치 읽기와 암호화된 BLE GATT 전송
- 장시간 비활동 감지 후 저전력 상태 전환
- 선택적으로 간단한 모션 게이트나 반복 후보 신호 계산
- 휴대폰 연결이 잠시 끊겼을 때를 위한 작은 순환 버퍼 유지

### 3.2 모바일의 역할

- 운동 세션 시작, 종료, 복구
- 개발 중 라벨링된 원시 데이터 저장
- 세션 분할, 운동 분류, 반복 횟수 모델 실행
- 신뢰도 표시와 불확실한 결과 확인 요청
- 사용자 수정, 중량, RPE(자각운동강도) 입력 수집
- 운동 및 근육군별 자극 요약 생성

### 3.3 클라우드의 역할(사용하는 경우)

- 모델 학습과 버전 관리
- 고정된 사용자 단위 테스트 세트에 대한 후보 모델 평가
- 동의한 학습 데이터를 삭제·보존 정책과 함께 저장
- 원시 움직임 업로드를 기본값으로 요구하지 않는 집계 오류 지표 모니터링

클라우드 처리는 선택 사항이다. 일반적인 운동 요약과 추론은 오프라인에서도 사용할 수 있어야 한다.

## 4. 인식 파이프라인

헬스장 방문 전체를 하나의 분류기에 넣기보다 계층형 파이프라인이 적합하다.

1. **세션 게이트:** 운동 가능성이 있는 활동과 비활동 시간을 구분한다.
2. **운동/휴식 분할:** 준비·전환 상태를 유지하면서 세트 후보 경계를 찾는다.
3. **운동 분류:** 지원 운동 중 하나 또는 `unknown`을 예측한다.
4. **반복 단계 탐지:** 분류된 세트 안에서 완전한 동작 주기를 찾는다.
5. **세트 집계:** 유효 반복을 묶고 시간·휴식 조건을 적용한다.
6. **신뢰도 정책:** 높은 신뢰도의 결과는 자동 확정하고 불확실한 결과는 수정을 요청한다.

`unknown`, `transition`, `non-exercise` 클래스는 필수다. 정제된 운동 클립만 학습한 모델은 휴대폰 사용, 원판 옮기기, 기구 조절, 걷기를 운동으로 잘못 분류한다.

### 4.1 권장 모델 발전 순서

1. 신호 품질 검사와 규칙 기반 peak counting 기준선을 만든다.
2. Random Forest 또는 Gradient Boosting 같은 작은 특징 기반 모델로 운동/휴식 분할과 운동 분류를 시작한다.
3. 원시 윈도우를 사용하는 1D CNN 또는 Temporal Convolutional Network와 비교한다.
4. 하나의 범용 임계값을 강제하기보다 운동 종류를 조건으로 사용하는 반복 검출기를 평가한다.
5. 오프라인 동작을 실질적으로 개선하고 측정된 엣지 메모리·전력 예산에 들어가는 모델만 양자화하여 보드로 옮긴다.

모델 선택은 무작위 윈도우 정확도보다 사용자 독립 결과, 지연 시간, 배터리 소비를 기준으로 해야 한다.

## 5. 운동 범위와 예상 한계

### 5.1 권장 MVP 운동

손목 움직임과 저항이 강하게 연결된 운동을 우선한다.

- 덤벨 바이셉스 컬
- 덤벨 또는 머신 숄더 프레스
- 덤벨 레터럴 레이즈
- 시티드 케이블 로우
- 랫풀다운
- 트라이셉스 푸시다운
- 체스트 프레스 또는 벤치프레스
- 파일럿 분리도 시험 후 선정하는 운동 1개

손목 신호가 거의 같은 머신 변형을 처음부터 많이 포함하지 않는다. 손목 신호와 사용자 가치가 안정적인 구분을 정당화하지 못하면 클래스를 합친다.

### 5.2 어렵거나 지원하기 힘든 경우

- 손목이 거의 움직이지 않는 레그프레스, 레그컬, 카프레이즈 등 하체 머신 운동
- 스쿼트 깊이, 무릎 정렬, 세부 자세 평가
- 강한 주기성 손목 신호가 없는 플랭크 같은 등척성 운동
- 움직임만 이용한 중량 또는 힘 추정
- 밴드가 없는 팔로 주로 수행한 편측 운동
- 손목 궤적이 거의 같은 운동 변형
- 느슨한 스트랩, 반대 방향 착용, 손목 변경, 세트 중 휴대폰 잡기

제한된 운동 목록을 사용한 통제 연구에서는 손목 기반 인식도 높은 성능을 보였다. 한 스마트워치 연구는 손목만 사용한 운동 인식 98.91%, 세트의 91%에서 ±1회 이내 반복 횟수를 보고했다. 그러나 이 수치는 제품 보증값이 아니다. 37개 운동을 포함한 다른 연구에서는 손목 하나의 운동군 분류 정확도가 75%였고, 하체 움직임은 다른 신체 위치 센서가 더 유리했다. 실제 헬스장의 전환 동작, 처음 보는 사용자, 기구 차이, 미지원 운동은 정제된 실험 클립보다 성능을 낮춘다.

## 6. 데이터셋 설계

서로 보완하는 두 종류의 데이터가 필요하다.

### 6.1 통제된 운동 기록

지원 운동마다 정답을 알고 있는 상태에서 다양한 수행 방식을 기록한다.

- 유의미한 첫 검증을 위한 참가자 20~50명
- 서로 다른 체형, 운동 경험, 주사용 손, 동작 습관
- 운동당 3~5세트, 세트당 약 8~15회
- 여러 중량, 템포, 가동 범위, 그립, 피로 수준
- 제품이 양쪽 착용을 허용한다면 좌우 손목 모두
- 단단함, 보통, 약간 느슨한 스트랩 조건
- 정상 반복, 불완전 반복, 일시 정지, 중단된 세트

### 6.2 연속 헬스장 세션

전체 세션에는 다음을 포함한다.

- 걷기와 서 있기
- 휴대폰 사용과 물 마시기
- 기구 조절과 원판 옮기기
- 워밍업과 가동성 운동
- 휴식과 대화
- 미지원 운동
- 기구 사이의 이동
- 모호한 세션 시작과 종료

연속 세션에는 파일 전체의 운동 이름 하나가 아니라 세트와 반복 시점 라벨을 기록해야 한다. 참가자의 명시적 동의를 받고 영상 보호와 삭제 정책을 적용한다면 동기화 영상이 개발 단계의 가장 실용적인 정답 자료다.

### 6.3 최소 기록 스키마

| 필드 그룹 | 필드 |
|---|---|
| 샘플 | 세션 ID, 장치 시간, 순번, accel x/y/z, gyro x/y/z |
| 장치 | 펌웨어 버전, 보드 리비전, IMU 범위/ODR, 착용 손목, 방향 |
| 참가자 | 가명 ID, 주사용 손, 선택적 집단 속성 |
| 세트 라벨 | 운동명, 세트 시작/종료, 반복 시작/종료, 정상/불완전 반복 |
| 운동 맥락 | 중량, 목표 템포, RPE, 기구, 그립/스탠스 변형 |
| 품질 | 스트랩 조임, 패킷 손실, 영상 유무, 라벨러/신뢰도 |

이름, 이메일 주소 등 직접 식별자를 모델 키로 사용하지 않는다.

### 6.4 데이터 분할

무작위 윈도우가 아니라 참가자 단위로 나눈다. 한 사람의 세션에서 나온 윈도우가 학습과 테스트에 동시에 들어가면 안 된다. 권장 평가 방식은 다음과 같다.

- 개발: 참가자 단위 학습/검증 분할
- 모델 선택: Leave-One-Subject-Out 또는 그룹 교차 검증
- 최종 보고: 한 번도 사용하지 않은 고정 참가자 단위 테스트 세트
- 선택적 개인화: 사용자 독립 모델과 별도 결과로 보고

특정 기구나 헬스장에 대한 일반화 성능을 주장하려면 해당 기구 인스턴스나 장소 전체를 별도로 제외한 시험도 수행한다.

## 7. 검증 및 출시 기준

### 7.1 모델 지표

| 기능 | 필요한 지표 |
|---|---|
| 운동 분류 | Macro-F1, balanced accuracy, 클래스별 precision/recall, confusion matrix, unknown 거절 성능 |
| 세트 탐지 | 명시된 경계 허용 오차에서 event precision/recall/F1 |
| 횟수 계산 | 평균 절대 오차, 중앙값 절대 오차, ±1회·±2회 이내 세트 비율 |
| 연속 동작 | 시간당 오탐 세트, 세트 누락률, 세션 전체 정확도 |
| 시스템 품질 | BLE 손실, 시간 지터, 추론 지연, 전류, 사용 시간, 열 특성 |

겹치는 많은 윈도우가 하나의 쉬운 세트에서 나올 수 있으므로 윈도우 정확도만으로는 부족하다.

### 7.2 제안 MVP 출시 기준

- 공개된 운동 클래스 5~8개와 `unknown`
- 고정 참가자 단위 테스트 세트에서 Macro-F1 0.80 이상
- 정확히 식별된 세트 중 85% 이상이 실제 횟수의 ±1회 이내
- 전체 세션에서 허용할 수 있는 오탐 세트 비율. 구체적인 수치는 파일럿 데이터 후 확정
- 지원되는 휴대폰 거리 조건에서 BLE 패킷 손실 1% 미만
- 완성된 프로토타입에서 안전 여유를 포함한 운동 세션 길이의 배터리 사용 시간 입증
- 모든 결과를 앱에서 수정할 수 있고 낮은 신뢰도 결과를 명확히 표시

이는 공학적 시작 기준이며 의료 또는 모든 운동에 대한 성능 주장이 아니다.

## 8. 근육 사용량과 성장 표현

### 8.1 제공 가능한 출력

앱은 투명한 **근육군별 훈련 자극 추정치**를 계산할 수 있다.

```text
자극(근육군) = 합계(
  운동별 근육 기여도
  x 완료 세트
  x 완료 반복 횟수
  x 입력한 중량 또는 상대 강도
  x 노력도 / 템포 보정
)
```

이 값은 운동 기록을 이용한 추정치라고 설명해야 한다. 중량이나 노력도가 없다면 허위 훈련 볼륨을 만들지 말고 신뢰도가 낮은 상대 점수를 제공한다.

유용한 출력은 다음과 같다.

- 운동별 세트와 반복 횟수
- 입력한 볼륨 로드(적용 가능한 경우 `세트 × 횟수 × 중량`)
- 운동한 주동근과 보조근
- 주간 볼륨 추세
- 자극 및 회복 추정 추세
- 개인 운동 일관성과 점진적 향상

### 8.2 제공하면 안 되는 주장

다음을 기기가 측정했다고 표현해서는 안 된다.

- 근육 활성 비율
- 근육 손상
- 임상 수준 정밀도의 칼로리
- 한 번의 운동이 만든 근비대
- 근육이 성장한 밀리미터 또는 백분율
- 부상 위험 또는 의료적 회복 상태

장기 성장 평가에는 일관된 둘레나 영상 측정, 체성분, 중량 기록, 영양, 수면, 회복 정보가 추가로 필요하다. 이 정보가 있어도 결과는 추세 추정치이지 IMU의 직접 측정값이 아니다.

## 9. 개인정보, 안전, 보안

- 오디오 수집을 기본 비활성화하고 MVP에서는 사용하지 않는다.
- 선택한 스택이 지원하는 인증 페어링, 암호화 BLE 특성, 서명 펌웨어를 사용한다.
- 가명 참가자 ID를 사용하고 신원 정보는 별도로 보관한다.
- 연구 기록, 특히 동기화 영상에는 명시적 동의를 받는다.
- 데이터 수집 전 보존·삭제 기간을 정한다.
- 원시 센서 업로드는 옵트인으로 하고 요약은 로컬에 둘 수 있게 한다.
- 배터리 종류, 극성, 충전 전류, 케이스 환기, 충전 시험을 문서화한다.
- 프로토타입을 의료기기나 진단 도구로 홍보하지 않는다.

움직임 패턴은 개인을 식별할 가능성이 있고 건강 관련 개인정보에 가깝다. 이름이 포함되지 않아도 보안과 동의 요건이 적용된다.

## 10. 개발 로드맵

### 단계 0: 보드 특성 확인(1~2주)

- 실제 보드 리비전과 외부 플래시 실장 여부 확인
- IMU 축, 범위, 타임스탬프 안정성, FIFO, 인터럽트, BLE 처리량 검증
- 대기, 기록, 송신, 연결 해제, 절전 상태 전류 측정
- 안전한 배터리 모니터링과 50/100 mA 충전 동작 확인

### 단계 1: 로거와 파일럿 데이터(2~3주)

- 100 Hz 가속도·자이로 데이터 프로토콜 구현
- 모바일 기록, 라벨링, 수정 흐름 구현
- 작은 통제 파일럿과 연속 부정 예제 수집
- 분리 가능한 운동 5~8개 선정

### 단계 2: 기준 추론 모델(3~4주)

- 모션 게이트와 운동/휴식 분할 구현
- 특징 모델과 peak counting 기준선 구축
- 운동 조건부 반복 횟수 계산과 `unknown` 거절 추가
- 참가자 단위 분할로 평가

### 단계 3: 전체 세션 검증(3~4주)

- 참가자 20~50명의 연속 헬스장 세션 수집
- 운동 목록과 테스트 세트 고정
- 정확도, 시간당 오탐 세트, BLE 신뢰성, 배터리 사용 시간 평가
- 수정 UX와 신뢰도 정책 개선

### 단계 4: 엣지 최적화와 베타(3~4주)

- 100 Hz와 50 Hz 제품 설정 비교
- 배터리, 개인정보 또는 오프라인 사용을 개선할 때만 양자화 모션 게이트나 반복 모델을 보드에 이식
- 실제 헬스장 베타 테스트와 지원·미지원 조건 공개

## 11. 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 손목에서 하체 움직임이 보이지 않음 | 운동 누락 또는 혼동 | 주장 범위 제한, 추후 추가 센서나 기구 연동 |
| 정제된 클립에 과적합 | 실험실 성능은 좋지만 헬스장 성능 저하 | 연속 세션과 어려운 부정 예제 수집 |
| 참가자 데이터 누출 | 부풀려진 검증 결과 | 모든 분할을 참가자 단위로 수행 |
| 보드 저장 공간 불확실 | 데이터 손실 또는 펌웨어 초과 | 리비전/BOM 확인, 외부 플래시에 의존하지 않음 |
| BLE 중단 | 샘플과 횟수 누락 | 순번, 순환 버퍼, 재연결 복구 |
| 스트랩 이동과 착용 방향 | 신호 변화와 오분류 | 방향 보정, 착용 안내, 데이터 증강 |
| 데이터시트 기반 배터리 추정 | 실제 사용 시간 미달 | 조립된 전체 시스템 측정 |
| 근육 성장 과장 | 신뢰 및 규제 위험 | 투명한 자극·추세 추정치만 제공 |

## 12. 결론

범위가 명확한 프로토타입에는 XIAO nRF52840 Sense를 사용해도 좋다. 이 보드는 운동 추적 밴드에 필요한 움직임 신호 수집, 통신, 가벼운 처리를 수행할 수 있다. 가장 큰 과제는 프로세서 성능이 아니라 대표성 있고 정확하게 라벨링된 사용자 독립 데이터를 확보하고 정직한 지원 운동 범위를 정하는 것이다.

첫 제품 주장은 **공개된 지원 운동 목록에 대한 세트·반복 횟수 자동 기록과 사용자 수정 기능**이어야 한다. 근육군별 자극은 계산 방법을 설명하는 파생 추정치로 추가할 수 있다. 근육 활성도와 근육 성장량의 직접 측정은 센서의 주장 범위에서 제외한다.
